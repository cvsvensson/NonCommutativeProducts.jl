API reference

No names are exported, so access them as NonCommutativeProducts.name or import them explicitly, e.g. using NonCommutativeProducts: @nc, terms.

NonCommutativeProducts.NonCommutativeProducts — Module
NonCommutativeProducts

Symbolic arithmetic with atoms that do not commute. Atoms are registered with @nc. Products are NCMul values and sums are NCAdd values. The order of factors is set by defining mul_effect for the atom types, and autosorting during multiplication is controlled by enable_autosort!, disable_autosort! and with_autosort.

NonCommutativeProducts.@commutative — Macro
@commutative T1 T2 ...

Define mixed arithmetic for types that commute with each other, and order them as listed: mul_effect(x::Ti, y::Tj) is nothing if i < j and y * x if i > j. The types must already be registered with @nc.

NonCommutativeProducts.mul_effect — Function
mul_effect(a, b)

When sorting a non-commutative expression, this function defines what a*b should be replaced by. It must have a branch that returns nothing in order for the sorting to terminate.

No methods for mul_effect are defined in this package, so you need to define them for your types.

The return value can be nothing, a number, an object, a sum or product of these, or one of the helper types Swap(λ) (replace a*b by λ*b*a) and AddTerms(terms) (replace a*b by a sum of terms). Swap and AddTerms are available as NonCommutativeProducts.Swap and NonCommutativeProducts.AddTerms.

Example

# Anticommuting Grassmann numbersstruct θ id::Int endNonCommutativeProducts.@nc θNonCommutativeProducts.mul_effect(a::θ, b::θ) = a.id < b.id ? nothing : -b * a * (a.id==b.id ? 0 : 1)NonCommutativeProducts.enable_autosort!()θ(2)*θ(1) # = -θ(1)*θ(2)θ(1)*θ(1) # = 0
source
NonCommutativeProducts.Swap — Type
Swap(λ)

Return value for mul_effect that replaces a*b by λ*b*a.

NonCommutativeProducts.AddTerms — Type
AddTerms(terms)

Return value for mul_effect that replaces a*b by the sum of terms. terms is an iterable such as a vector or a tuple, and its elements can be any other allowed return value of mul_effect except nothing, including sums and nested AddTerms.

Gradings

NonCommutativeProducts.grade — Function
grade(atom)

The grade of atom. Define it for your types to make them graded; the default for types declared with @nc is nothing, the identity grade. For other objects it throws an ArgumentError. Every term of mul_effect(a, b) must have the product of the grades of a and b, see check_grading. Within one grading, this is mul_grade(grade(a), grade(b)). Grades of different types are combined according to their grading.

For other expressions, grade(x) == only(grades(x)), and it throws an ArgumentError if there are several grades or none.

Example

# Fermions with charge as the gradeNonCommutativeProducts.grade(f::Fermion) = f.dagger ? 1 : -1NonCommutativeProducts.mul_grade(g::Int, h::Int) = iszero(g + h) ? nothing : g + hNonCommutativeProducts.adjoint_grade(g::Int) = -g
source
NonCommutativeProducts.mul_grade — Function
mul_grade(g, h)

The product of the grades g and h of one grading, neither of which is nothing. It must be associative, and return nothing for the identity grade or else a grade of the same grading.

It is only called for grades of one grading: grades of the same type, or of different types with the same grading. So a family of types sharing a key needs mul_grade methods between its member types. Grades of different gradings are combined into a ProductGrade instead.

source
NonCommutativeProducts.adjoint_grade — Function
adjoint_grade(g)

The grade of the adjoint of an expression of grade g (not nothing). It must return nothing or a grade of the same grading. Only needed for adjoints of zero sums.

source
NonCommutativeProducts.grading — Function
grading(G::Type)

The key of the grading that grades of type G belong to, or nothing if it is undeclared (the default). Keys are compared with isequal, and should be types or symbols.

Grades of the same type are multiplied with mul_grade, and need no declaration. Grades of different types are combined by their keys:

  • equal keys: one grading, multiplied with mul_grade, which must be defined between the types;
  • different keys: independent gradings, combined into a ProductGrade;
  • an undeclared key: an ArgumentError.

Example

NonCommutativeProducts.grading(::Type{Charge}) = ChargeNonCommutativeProducts.grading(::Type{<:U1}) = U1 # one grading spread over the types U1{T}
source
NonCommutativeProducts.ProductGrade — Type
ProductGrade(g1, g2, ...)

A grade in the direct product of independent gradings, with one component per grading. It is the product of grades with different declared gradings, so that e.g. fermions graded by Charge and kets graded by Bicyclic can be multiplied without defining mul_grade(::Charge, ::Bicyclic), once both types declare their grading.

Products involving a ProductGrade are computed componentwise:

  • components of the same grading are multiplied with mul_grade, in order, so the product is associative;
  • components that become nothing are dropped, and a single remaining component is returned unwrapped, so the product of the grades Charge(1), Bicyclic(1, 0) and Charge(-1) is Bicyclic(1, 0).

Components are matched by grading regardless of their order, so f * k and k * f have the same grade. adjoint_grade acts componentwise. mul_grade and adjoint_grade within one grading must return a grade of that grading or nothing, and this is checked. Construct a ProductGrade with at least two components, in any order, with distinct declared gradings, none of them nothing or a ProductGrade.

Example

# Fermions with spin, graded by charge and by spin, using `Charge` from the example in the READMEstruct Spin    s::Intendspin(s) = iszero(s) ? nothing : Spin(s)NonCommutativeProducts.grading(::Type{Spin}) = Spin # and likewise for ChargeNonCommutativeProducts.mul_grade(a::Spin, b::Spin) = spin(a.s + b.s)NonCommutativeProducts.adjoint_grade(a::Spin) = spin(-a.s)NonCommutativeProducts.grade(f::SpinfulFermion) = ProductGrade(Charge(f.dagger ? 1 : -1), Spin(f.up == f.dagger ? 1 : -1))
source
NonCommutativeProducts.grades — Function
grades(x)

The set of grades of x. Grades never affect ==, hash or any other property of the value.

For a nonzero x, these are the grades of its terms, plus nothing if it has a nonzero scalar part. A zero has the grades of how it was computed, from the grades Γ(a), Γ(b) of the operands:

operationgrades of a zero result
a * b, a^nΓ(a) ⊗ Γ(b) = {g ⋅ h : g ∈ Γ(a), h ∈ Γ(b)}
a + b, a - bΓ(a) ∪ Γ(b)
a'{adjoint_grade(g) : g ∈ Γ(a)}
α * a, zero(a), zerovector(a), copy, convert, sortΓ(a)
mul!!(c, a, b)Γ(c) ∪ Γ(a) ⊗ Γ(b)
add!!(a, b, α, β), VectorInterface.add(!)Γ(a) ∪ Γ(b), or Γ(b) if β isa VectorInterface.Zero

Here g ⋅ h is the product of grades, mul_grade within one grading (see grading).

A zero without such a history (the number 0, zero(typeof(a)), or a zero sum built from a Dict or by ncmap) has no grades. The empty set is the unit of both ⊗ and ∪.

A product without factors behaves like its prefactor, a number, so a zero one has no grades: grades(2 * one(f)) is Set([nothing]), but grades(0 * one(f)) is empty. The table applies to products with factors and to sums.

Example

f = Fermion(1) # with the charge grading in the example of `grade`grades(f' * f + 1) == Set([nothing])grades(f * f) == Set([-2]) # f * f == 0grades(0 * (f' + f)) == Set([1, -1])

NonCommutativeProducts.grade_part — Function
grade_part(x, g)

The part of x with grade g, where the scalar part has grade nothing. x is the sum of grade_part(x, g) over g in grades(x).

Example

f = Fermion(1) # with the charge grading in the example of `grade`grade_part(f' * f + f + 1, nothing) == f' * f + 1grade_part(f' * f + f + 1, -1) == f

NonCommutativeProducts.check_grading — Function
check_grading(a, b)

Check that every term of mul_effect(a, b) has the product of the grades of a and b (see grade). Zero terms are always allowed. Meant to be used in tests.

Example

f = Fermion(1)check_grading(f, f') # true

Sorting

Base.sort — Method
sort(x::Union{NCMul,NCAdd})

Sort x by repeatedly applying mul_effect to neighbouring factors. The result is always an NCAdd, also when x is a product that sorts to a single term.

disable_autosort!()

Do not sort products as they are formed, unless overridden by with_autosort. This is the default.

NonCommutativeProducts.autosort — Function
autosort()

Whether products are sorted with mul_effect as they are formed. Set the global default with enable_autosort! and disable_autosort!, or override it for a block of code with with_autosort. Autosorting is off by default.

source
NonCommutativeProducts.with_autosort — Function
with_autosort(f, enabled::Bool=true)

Call f() with autosorting set to enabled, overriding the global setting from enable_autosort! and disable_autosort! for the duration of the call. Works with a do block:

with_autosort(false) do    a * bend

Expressions

NonCommutativeProducts.NCMul — Type
NCMul

A product: a coefficient times an ordered list of factors. Create products by multiplying atoms registered with @nc, e.g. 2 * a * b. Use coefficient(x) and factors(x) to read the parts of a product.

source
NonCommutativeProducts.NCAdd — Type
NCAdd

A sum of products (NCMul) with a scalar term. Create sums by adding atoms and products, e.g. a*b + 2*c + 1. Use terms(x) to iterate over the terms of a sum.

The constructors of NCAdd are internal. They may take ownership of the dictionary passed to them and mutate it.

source
NonCommutativeProducts.terms — Function
terms(x)

An iterator over the terms of x, each an NCMul that includes its coefficient. A nonzero scalar part of a sum appears as a product without factors, so sum(terms(x)) == x. Zero has no terms: terms(0), the terms of a zero sum and the terms of a zero product are empty, and sum of an empty iterator throws.

Works for sums, products, numbers and atoms registered with @nc.

Example

collect(terms(2 * a * b + 3 * c + 1)) # the products 2*a*b, 3*c and 1, in no particular orderterms(2 * a) # the single product 2*a
source
NonCommutativeProducts.factors — Function
factors(x)

The factors of x as an AbstractVector, in order and without the coefficient. Works for products, numbers and atoms registered with @nc: a number has no factors, and an atom is its own single factor. A sum with exactly one term has the factors of that term. A sum with more terms throws an ArgumentError; use terms to get its products. The result is a copy, so modifying it does not change x.

Example

factors(2 * a * b) == [a, b]factors(2) == []factors(a) == [a]
source
NonCommutativeProducts.coefficient — Function
coefficient(x)

The scalar coefficient of x. Works for products, numbers and atoms registered with @nc: a number is its own coefficient, and an atom has coefficient 1. A sum with exactly one term has the coefficient of that term. A sum with more terms throws an ArgumentError; use terms to get its products.

Example

coefficient(2 * a * b) == 2coefficient(2) == 2coefficient(a) == 1
source
NonCommutativeProducts.scalar — Function
scalar(x)

The number that x equals if x is a scalar, i.e. a number or a product or sum without factors. Throws an ArgumentError for other products and sums.

source
NonCommutativeProducts.add!! — Function
add!!(a, b)
add!!(a, b, α, β)

Compute a + b, or β * a + α * b, reusing the storage of a when possible. Use the returned value, since a may be left unchanged or modified. This function belongs to this package and is not VectorInterface.add!!. It differs in having the 2-argument form, and in the weights α and β defaulting to One(), so that add!!(a, b) is a + b. Methods for VectorInterface.add!! call it.

source
NonCommutativeProducts.ncmap — Function
ncmap(f, expr)

Map f over the noncommutative factors in expr.

Example

If a and b are of types registered with @nc then 

ncmap(f, 2*a*b + 1) == 2*f(a)*f(b) + 1

See ncmapreduce for more general mapping and reduction.

source
NonCommutativeProducts.ncmapreduce — Function
ncmapreduce(f, ops, expr; scalarmap=identity)

Map f over the noncommutative factors in expr and combine terms with custom binary operations in ops = (add, mul). Scalars are transformed with scalarmap. Each term is reduced with mul and then the terms are reduced with add. Uses foldl for the ordering of operations.

Example

(using infix notation for add and mul)

ncmapreduce(f, (add, mul), 2*a*b + 1; scalarmap=g) == g(1) add ((g(2) mul f(a)) mul f(b))
