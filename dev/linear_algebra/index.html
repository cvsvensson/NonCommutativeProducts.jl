Linear algebra

Expressions implement VectorInterface.jl, with the inner product inner(x, y) = scalar(x' * y). This requires adjoint to be defined for your types, and x' * y must sort to an expression with no factors left, so that scalar can extract its value. inner sorts x' * y whether or not autosort is enabled.

With KrylovKit.jl loaded, expressions can also be used as linear operators acting by left multiplication. These features live in a package extension, which using KrylovKit loads.

Example: Let's define kets and bras and exponentiate a Hamiltonian:

julia> using KrylovKit, LinearAlgebrajulia> import NonCommutativeProducts as NCjulia> NC.enable_autosort!();julia> struct Ket           n::Int           bra::Bool           Ket(n::Int, bra::Bool=false) = new(n, bra)       endjulia> Base.show(io::IO, k::Ket) = print(io, k.bra ? "⟨" : "|", k.n, k.bra ? "|" : "⟩")julia> Base.adjoint(k::Ket) = Ket(k.n, !k.bra)julia> NC.@nc Ketjulia> NC.mul_effect(a::Ket, b::Ket) = a.bra && !b.bra ? Int(a.n == b.n) : nothingjulia> k0, k1 = Ket(0), Ket(1);julia> H = k0 * k1' + k1 * k0'|0⟩*⟨1| + |1⟩*⟨0|julia> vals, vecs = eigsolve(H, k0, 2, :SR; ishermitian=true);julia> x, info = exponentiate(1im*H, pi/2, k0);julia> norm(x - im*k1) < 1e-12true

Fast inner products

inner(x, y) forms a' * b for every pair of a term a of x and a term b of y, so its cost is proportional to the product of the numbers of terms. With contraction_key defined, inner skips the pairs whose first factors have different keys, which takes time proportional to the number of terms when each key matches few terms.

Keys must not change the result of sorting x' * y; the docstring lists the conditions. For example, if an operator O had mul_effect(O', ⟨1|) = ⟨2|, then (|1⟩O)' * |2⟩ would sort to ⟨2|2⟩ = 1, so kets could not have keys.

For the kets above, ⟨n|m⟩ is zero unless n == m, and nothing acts on a bra from the left, so kets are keyed by their label. Bras get no key, since ⟨1|' * ⟨2| = |1⟩⟨2| is nonzero.

julia> NC.contraction_key(k::Ket) = k.bra ? nothing : k.njulia> using NonCommutativeProducts.VectorInterface: innerjulia> inner(k0 + 2k1, k1)2
